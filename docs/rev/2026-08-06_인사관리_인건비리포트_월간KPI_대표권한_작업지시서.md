### 1.2 증감율 계산 규칙 (엑셀 `분석` 시트 검증)

엑셀은 지표 성격에 따라 **두 가지 방식을 섞어 쓴다**. 삼국유통 실측:

| 지표 | 대조 기간 | 현재 | 엑셀 증감 | 계산 방식 |
| --- | --- | --- | --- | --- |
| 매출 | 82,652,900 | 115,377,000 | 0.395922 | **비율** `(현재−과거)÷과거` |
| 이익률 | 0.2589592 | 0.2546863 | −0.0042728 | **차분** `현재−과거` (%p) |
| 평균 근무인원 | 2.88 | 2.8095238 | −0.0244709 | **비율** |
| 인당생산성 | 1,147,957 | 1,955,542 | 0.7034980 | **비율** |

→ **비율 지표(이익률·매출대비 재고비율)만 %p 차분, 나머지는 % 비율.** 이 관행을 그대로 따른다(§5.6).

### 1.3 팀장 = 매장 책임자, 그러나 직급은 일별 배정이다

**Evidence**

- `평균 재고` 시트가 매장별 · **월별 팀장 1명**을 `평균재고 / 매출대비 재고비율 / 마진율` 옆에 기록한다 (삼국유통-홍윤선, 강서수산-정상권, 제일수산-이호복, 불광수산-장대웅, 안양참수산-김주석→김기옥).
- → 요청 1-12 `팀장들만 '월간 생산성/인력 배치 분석'`의 의미가 규명된다. **분석 행 단위를 매장 책임자(팀장)로 두겠다**는 뜻이다.
- `입력` 시트는 **하루 단위로 팀장 열 2개 · 팀원 열 12개**를 따로 둔다.
- 팀장 등장 **167명**, 팀원 등장 **392명**, 양쪽 등장 **148명**. 그중 **140명이 팀장 기간과 팀원 기간이 겹친다** (예: `차선효` 팀장 2021-06-14~2023-11-18 / 팀원 2021-06-11~2023-04-24).

**판정**

- **직급은 사람에 고정된 속성이 아니다.** 같은 사람이 같은 시기에 날짜별로 역할이 바뀐다. 승진 이력이 아니라 일별 배정이다.
- `Employee.position` 하나로는 요청 1-12를 구현할 수 없다. 그날의 역할은 `LedgerLaborItem`에 있어야 한다.
- 요청 1-11 `직급 표시`는 인사관리 카드 요구이므로 사람의 기본 직급으로 충분하다. **이번 범위는 여기까지다.**
- 요청 1-12는 선행 조건이 있다 → §7 D-5.

### 1.4 리스크 3건

#### R-1 (높음) — `영업이익` 용어가 고객 엑셀과 우리 시스템에서 다르다

- 고객 엑셀: `매출이익 − 영업이익`을 `근무인원`으로 나눈 값의 **중앙값 57,000원**(10~90분위 22,667~108,133). 명백히 **일당 인건비가 포함된 차감**이다.
- 우리 시스템: `operatingProfit = grossProfit − expenseTotal`, **인건비 미차감** (`ledger.ts:695-696`).
- → **고객의 “영업이익” ≈ 우리의 “순이익”**이다.
- 요청 3-2-1의 나열 `매출, 이익률, 영업이익, 인건비, = 순이익`이 정확히 이 구조를 표현하므로 **설계는 그대로 유효**하다.
- 단 화면에 계산식을 병기하지 않으면 두 “영업이익”을 같은 값으로 오해한다. **계산식 병기를 필수 요건으로 둔다** (§5.3, §5.6).

#### R-2 (중간) — 고객 핵심 지표 `인당생산성`·`평균 근무인원`이 요청 3 테이블에 없다

- 엑셀은 `분석`·`매장 별(년도)`·`매장 별(달)` 3시트 모두에서 8지표 고정 세트를 쓴다. `인당생산성`은 전용 시트까지 있다.
- 우리 `productivity`는 계산돼 있으나 `MonthlyClosingKpiSummary`에 없다 (`types.ts:267-283`). 비교 리포트에는 있다 (`queries.ts:3558`).
- → 의도적 제외인지 확인 필요 → §7 D-7. **단 §5.6의 기간 분석 탭에서는 8지표를 모두 싣는다**(엑셀 정렬이 목적이므로).

#### R-3 (낮음) — 고객 엑셀의 재고 지표는 전부 깨져 있다

- `평균재고`·`매출대비 재고비율`이 모든 시트에서 `#REF!`(참조 시트 삭제).
- 요청 3-1의 `매출대비 재고비율` 삭제 요구 배경으로 보인다. **엑셀에서 이미 못 쓰던 지표**다.
- 우리 시스템은 실제로 계산한다. 요청대로 월간에서는 내리되, **기간 분석 탭에는 살려 둔다**(대표가 “안 되는 줄 알았던 지표가 실제로 나온다”를 확인할 수 있어야 함).

## 2. 대표의 분석 모델 → 시스템 매핑

### 2.1 엑셀이 드러내는 4가지 뷰

대표는 6년치 데이터를 4가지 관점으로 반복 조회해 왔다.

| 뷰 | 엑셀 시트 | 축 | 용도 |
| --- | --- | --- | --- |
| **V1 기간 대조** | `분석` | 두 기간 × 전 매장 × 8지표 + 증감율 | “작년 6월 대비 올해 2월, 어느 매장이 좋아졌나” |
| **V2 연도 비교** | `매장 별(년도)` | 단일 매장 × **같은 월일 범위** × 연도별 | “안양점 6/1~6/30을 2020~2026 비교” (시즌 비교) |
| **V3 월 추이** | `매장 별(달)` | 단일 매장 × 연도 고정 × 1~12월 | “못골점 2026년 월별 흐름” |
| **V4 지표 피벗** | `매출`·`매출이익`·`이익률`·`인당생산성` | 지표 1개 × 전 매장 × 월 시계열 | “전 매장 이익률을 한 판에” |

8지표 고정 세트(순서 그대로): **매출 · 매출이익 · 이익률 · 평균 근무인원 · 인당생산성 · 평균재고 · 평균매출 · 매출대비 재고비율**

## 4. 현행 코드 검토 결과

### 4.1 직원 마스터에 인사 정보 컬럼이 없다

**Evidence**

- `Employee` 필드는 `name`, `hireDate`, `isActive`, `dailyWage`, `desiredInsuranceAmount`, `desiredCashAmount`뿐이다 (`prisma/schema.prisma:956-973`).
- 폼 스키마도 동일 6필드 (`src/features/labor/employees-schemas.ts:23-40`).
- 조회 DTO·쿼리도 같은 필드만 선택 (`src/features/labor/employees-queries.ts:5-14`, `:84-109`).
- 생성/수정 액션이 그대로 write (`src/features/labor/employees-actions.ts:45-55`, `:80-91`).
- 화면은 폼 + 단일 테이블. **검색·상세 패널·직급 표기 없음** (`employee-management-client.tsx:205-419`).
- 입사일은 이미 필수 입력이다 (`employees-schemas.ts:33-35`).

**판정** — 요청 1-4(입사일)는 **이미 충족**. 4개 컬럼 신설 필요. 계좌번호·주소·연락처는 개인정보이므로 요청 5의 권한 게이트가 **필수 요건**이며 선택 사항이 아니다.

### 4.2 희망 현금은 저장된 입력값이고 단위가 맞지 않는다

**Evidence**

- `desiredCashAmount`는 Employee에 직접 저장 (`prisma/schema.prisma:966-968`).
- 인건비 리포트가 저장값을 그대로 읽는다 (`headquarters-labor-queries.ts:180-181`, `headquarters-labor-report.tsx:136`, `:161-163`).
- 상세 행 단위는 **영업일 × 근무자** (`headquarters-labor-queries.ts:167-183`). 희망 4대보험/현금은 **월 단위 금액** (`prisma/schema.prisma:964-965` 주석).
- 즉 일별 행에 월 금액을 반복 표시하고 있어 합계를 낼 수 없다.

**판정** — 요청 1-5와 요청 2는 같은 변경의 앞뒤다. 일별 행에 월 파생값을 넣을 수 없으므로 **근무자 월 정산 섹션 신설**이 필요하다.

### 4.3 인건비 리포트 필터가 월 단위로 고정돼 있다

**Evidence**

- 월 파라미터는 `^\d{4}-(?:0[1-9]|1[0-2])$`로만 받고 범위가 고정 생성된다 (`headquarters-labor-queries.ts:12`, `:58-75`).
- 페이지 필터는 `<Input type="month">` 하나 (`src/app/app/reports/labor/page.tsx:57-68`).
- DTO는 `monthInput` 단일 필드 (`headquarters-labor-types.ts:45-57`).
- 지점 요약은 `근무일 수 / 근무인원 합계 / 인건비 합계` 3개. 근무일 수 = `Set<영업일>.size`, 근무인원 합계 = 장부별 `workerCount` 합 (`headquarters-labor-queries.ts:222-245`).

**판정** — 일평균은 **쿼리 변경 없이 표시 계산만으로 가능**(0 나눗셈 가드 필요). 기간 필터는 DTO·쿼리·URL 계약을 함께 바꿔야 하며 기존 `?month=` 호환은 유지한다.

### 4.4 월간 핵심 성과는 카드 10개 그리드다

**Evidence**

- 카드 구성 (`monthly-closing-anomaly-report.tsx:118-215`): 고정 3개 — `장부 마감 매출`(:168-177) / `이월 매출`(:178-183) / `영업 매출 합계`(:184-195). `remainingItems` 7개 — 매출이익·이익률·영업이익·손실 합계·평균재고·평균매출·매출대비 재고비율 (:123-131). 인건비 (:205-213).
- DTO는 `MonthlyClosingKpiSummary` (`types.ts:267-283`). **`productivity` 없음**.
- **영업이익 = 매출이익 − 장부 지출**, 인건비 미차감 (`ledger.ts:695-696`).
- 인건비는 `IN_REVIEW`/`HEADQUARTERS_CLOSED` 장부의 `LedgerLaborItem.amount` 합계 (`queries.ts:2030-2044`).

**판정** — `순이익`은 신규 계산(`operatingProfit − laborAmount`). `operatingProfit`이 `null`이면 순이익도 `null`. 제거 지표는 DTO에서 지우지 않고 **화면에서만 내린다**(통합 리포트와 export가 계속 사용 — `tests/unit/hq-report-overview.test.mjs:1090-1091`).

### 4.5 매출 분석 3종은 일간 전용 데이터다

**Evidence**

- `DailySalesAnalysis` 3개 차트 (`daily-sales-analysis.tsx:104-190`): ① `salesChanges` **전일 대비** 증감률 ② `positions` 매출 비중/순위 ③ `inventoryRatios` 재고비율.
- 아침 회의 페이지 전용 (`src/app/app/reports/daily/page.tsx:183-188`). 출처는 **영업일 1일** 기준.
- 월간 리포트는 `selectedStoreId` 단일 지점 전제이며 미선택 시 본문을 안내 문구로 대체한다 (`monthly-closing-anomaly-report.tsx:45-52`).

**판정** — 컴포넌트는 재사용, 데이터는 월 기준 재계산. “전일 대비” → “전월 대비”. 지점 선택 분기 **바깥**에 둔다.

### 4.6 `기간 비교`는 단일 기간만 지원한다

**Evidence**

- 파라미터가 `startDate`/`endDate`/`storeId` 3개뿐이다 (`src/app/app/reports/comparison/page.tsx:15-19`, `:31-45`).
- 쿼리도 단일 range다 (`queries.ts:1498-1512`).

- 반면 테이블 지표는 엑셀 8지표 중 7개를 이미 보유한다 (§2.2, `store-comparison-report-table.tsx:56-66`).

**판정** — 두 기간 대조는 **기존 쿼리를 두 번 호출하고 증감을 계산**하면 된다. 신규 집계 로직이 필요 없다. 시계열 피벗도 같은 쿼리를 기간별로 반복 호출하는 구조다.

### 4.7 직원관리·인건비가 모든 리포트 사용자에게 열려 있다

**Evidence**

- 사이드바 두 메뉴 모두 `REPORT_VIEW` (`src/components/app-sidebar.tsx:34-46`).
- 리포트 네비게이션 `기간 분석` 그룹에도 `인건비` (`reports-nav.tsx:26-38`).
- 페이지 게이트도 `requireReportAccess()` (`reports/labor/page.tsx:27`, `labor/employees/page.tsx:17`).
- 쿼리 게이트도 동일 (`employees-queries.ts:85`, `headquarters-labor-queries.ts:276`).
- `REPORT_VIEW`는 `HQ_ADMIN`·`HQ_STAFF`·`CLOSE_MANAGER`·`UPLOAD_STAFF`·`SETTINGS_ADMIN`·`HQ_READONLY` **거의 모든 본사 프로필**이 보유 (`prisma/seed.ts:38-100`).
- **`OWNER`(대표/소유자) 프로필이 이미 존재**하며 모든 action 보유 (`prisma/seed.ts:30-37`).
- 네비게이션 필터가 `Object.values(PermissionAction)` 전체를 순회하므로 **enum 추가 시 자동 반영** (`app-sidebar.tsx:110-130`).

**판정** — 대표 프로필 신설 불필요. 기존 action 재사용 불가(`SETTINGS_MANAGE`는 기준정보 담당자가, `USER_PERMISSION_MANAGE`는 설정 관리자가 보유). **`LABOR_VIEW` 1개 신설**이 최소 변경이다. 쓰기 게이트 `requireEmployeeManageAccess()`가 `SETTINGS_MANAGE`를 쓰므로(`authz.ts:192-194`) 읽기만 좁히면 **볼 수 없는데 고칠 수 있는 상태**가 된다. 함께 좁힌다.

### 5.2 [B] 인건비 리포트 (요청 2)

#### 기간 필터

- 라디오 2모드: `월 선택`(기본) / `기간 지정`.
- URL: `?month=YYYY-MM`(기존 유지) 또는 `?from=&to=`. 둘 다 유효하면 `from/to` 우선.
- 검증: `from > to` 또는 366일 초과 시 **교환하지 말고 오류 메시지 + 현재 월 폴백**.
- DTO는 `monthInput` 유지(호환) + `rangeStart`/`rangeEnd`/`rangeLabel` 추가.

#### 근무인원 일평균 (2-1)

- `근무인원 합계` 오른쪽에 컬럼 1개.
- `= workerCount ÷ workdayCount`, **소수 둘째 자리까지**(엑셀 `평균 근무인원` 관행 — §1.1). `workdayCount = 0`이면 `-`.
- 서버 DTO를 늘리지 않고 표시 컴포넌트에서 계산한다.

#### 희망 현금 자동계산 — **D-1 승인 확정**

```
희망 현금(자동) = 해당 월 인건비 합계 − 희망 4대보험
```

- 음수는 **자르지 않고 그대로 표시 + 경고 배지**.
- 희망 4대보험 미입력 → `계산 불가 (희망 4대보험 미입력)`.
- 직원 미연결(자유 입력) → `계산 불가 (직원 미연결)`.

#### 표시 재구성

- **일별 상세**에서 `희망 4대보험`·`희망 현금` 컬럼 **제거**(단위 불일치가 원인 — §4.2).
- 상세 위에 **`근무자별 월 정산`** 섹션 신설:

  | 근무자 | 직급 | 근무일수 | 인건비 합계 | 희망 4대보험 | **희망 현금(자동)** | 계좌번호 |
  | --- | --- | --- | --- | --- | --- | --- |

- `희망 현금(자동)` 셀: 배경 강조 + `자동` 배지 + 계산식 툴팁.
- 계좌번호 컬럼은 §5.5 `LABOR_VIEW` 게이트 안에서만 렌더링.
- 다월 조회 시 `기간 합계 기준` 배지 + 희망 4대보험은 월 고정값이므로 **차감하지 않고** `기간 조회에서는 자동계산 미적용` 사유 표시.

### 5.3 [C] 월간 핵심 성과 테이블 (요청 3)

`MonthlyKpiSummary`(`monthly-closing-anomaly-report.tsx:118-215`)를 2행 테이블로 교체.

**1행 (강조)**

| 매출 | 이익률 | 영업이익<br>(매출이익 − 장부지출) | 인건비 | 순이익 (순이익률)<br>(영업이익 − 인건비) |
| --- | --- | --- | --- | --- |
| `salesAmount` | `grossMarginRate` | `operatingProfit` | `laborAmount` | **신규** |

**2행 (비강조)**

| 평균재고 | 손실 합계 | 평균매출 |
| --- | --- | --- |

**제거**: `장부 마감 매출`, `이월 매출`, `매출이익`, `매출대비 재고비율`

```
netProfit     = operatingProfit === null ? null : operatingProfit - laborAmount
netProfitRate = (netProfit === null || salesAmount <= 0) ? null : netProfit / salesAmount
```

- `netProfit`이 `null`이면 `operatingProfit`의 `unavailableReason`을 승계.
- 순이익률은 순이익 셀에 괄호 병기 (`-1,234,000원 (-3.2%)`).
- **R-1 대응 (필수)** — 헤더에 계산식 병기. 고객 엑셀의 “영업이익”은 인건비가 이미 빠진 값이라 우리 “영업이익”과 다르다.
- 정정 근거(`MetricValueWithEvidence`)는 기존 지표에 유지. 순이익은 파생값이므로 값만 표시하고 영업이익의 상태 배지를 함께 노출.
- DTO에서 제거 지표를 **삭제하지 않는다**. 화면에서만 내린다.
- 로딩 스켈레톤(`reports/monthly/loading.tsx`)도 테이블 형태로.

#### 5.6.4 모드 B — 기간 대조 ← 엑셀 `분석` 시트

**URL** `?mode=contrast&baseStart=&baseEnd=&startDate=&endDate=&storeId=`

**레이아웃** (엑셀 `분석` 시트와 동일한 3블록 세로 배치)

```
[대조 기간]  2025-06-01 ~ 2025-06-30     ← 엑셀 좌측 블록
  지점 × 8지표 테이블

[현재]       2026-02-01 ~ 2026-02-28     ← 엑셀 우측 블록
  지점 × 8지표 테이블

[과거 대비 현재 증감]                      ← 엑셀 하단 블록
  지점 × 8지표 테이블 (증감만)
```

**증감 계산 — §1.2 검증 규칙 그대로**

```
금액·인원·생산성 지표 → 비율:  (현재 − 과거) ÷ 과거        // % 표시
비율 지표(이익률, 매출대비 재고비율) → 차분:  현재 − 과거   // %p 표시
```

- 과거 값이 `0` 또는 `null`이면 증감은 `-`. **`Infinity`를 화면에 내보내지 않는다.**
- 어느 한쪽 기간이 `계산 불가`면 증감도 `계산 불가` + 사유 승계.
- 증감 부호에 색을 준다: 양수 강조 / 음수 경고. 단 **이익률·재고비율은 “높을수록 좋음”이 아니므로** 재고비율만 색 반전(재고비율 상승 = 경고).
- 기본값: `대조 기간`을 비우면 **직전 동일 길이 기간**을 자동 채운다. `getPreviousMonthComparisonRange`(`overview.ts:156`)의 로직을 기간 길이 기준으로 일반화해 재사용한다.

**구현** — 기존 `getHqStoreComparisonReport`를 **두 번 호출**하고 증감을 계산하는 얇은 래퍼 `getHqPeriodContrastReport`를 만든다. 신규 집계 로직을 작성하지 않는다.

#### 5.6.5 모드 C — 시계열 ← 엑셀 `매장 별(달)` · `매장 별(년도)` · 피벗 4종

**URL** `?mode=trend&axis=store|metric&unit=month|year&year=&metric=&storeId=&fromMonth=&toMonth=`

**컨트롤 3개**로 엑셀 4뷰를 전부 커버한다.

| 축(`axis`) | 단위(`unit`) | 결과 | 대응 엑셀 시트 |
| --- | --- | --- | --- |
| `store` (행=지점) | `month` | 지점 × 1~12월, 지표 1개 선택 | `매출`·`매출이익`·`이익률`·`인당생산성` 피벗 |
| `metric` (행=8지표) | `month` | 8지표 × 1~12월, 지점 1개 선택 | **`매장 별(달)`** |
| `metric` (행=8지표) | `year` | 8지표 × 연도별, 지점 1개 선택 | **`매장 별(년도)`** |
| `store` (행=지점) | `year` | 지점 × 연도별, 지표 1개 선택 | (보너스) |

- `unit=year`일 때 **월 범위 선택**(`fromMonth`/`toMonth`, 기본 1~12)을 제공한다. 엑셀 `매장 별(년도)`가 `6/1~6/30`을 고정하고 연도만 바꾸는 **시즌 비교**에 쓰이기 때문이다 (`매장 별(년도)` 시트 3행).
- 셀 값 없음 = `-`. 엑셀의 `0`·`#DIV/0!`을 그대로 흉내내지 않는다.
- 각 행 끝에 **합계/평균 열**을 둔다(금액은 합계, 비율은 가중평균).
- 표는 가로 스크롤 + 첫 열 고정(`sticky`). 12~7열 규모이므로 차트가 아니라 **표가 기본**이다. 대표가 보던 형태가 표다.
- 지표 1개 선택 모드(`axis=store`)에서만 하단에 꺾은선 차트 1개를 덧붙인다(`recharts` 기존 사용).

**구현** — 기간별로 `getStoreProfitSummariesForRange`를 반복 호출한다. `buildAllMonthsProfitAndLoss`(`monthly-profit-loss.ts:125-186`)가 이미 같은 패턴을 쓰고 있으므로 그 구조를 따른다.

```
// ponytail: 월 수가 수백 개로 커지면 단일 범위 쿼리 + in-memory 월별 그룹핑으로 바꾼다.
```
같은 주석을 남긴다(해당 파일 `:171`에 동일 선례 있음).

**성능 가드 (필수)** — 최대 조회 폭을 **36개 기간**으로 제한한다. 엑셀은 6년치(78개월)를 담고 있으나 한 화면에서 그만큼을 왕복 조회하면 응답이 무너진다. 초과 요청은 오류 메시지 + 최근 36기간으로 잘라 표시한다.

#### 5.6.6 Export

- 대표는 엑셀 사용자다. **각 모드에서 XLSX 내보내기가 핵심 가치**다.
- 기존 route `report=comparison`을 유지하고 `mode` 파라미터를 추가한다 (`src/app/api/reports/export/route.ts`).

  - 모드 C → 1시트 (화면 표 그대로)
- 감사 로그(`report.export.created`)는 기존 경로를 그대로 탄다. `mode`를 audit snapshot에 포함한다.

## 8. 수용 기준

### 8.1 [A] 직원 관리

- [ ] 인사관리 카드에 이름·**직급**·입사일·연락처·주소·계좌번호·하루 인건비·희망 4대보험이 있고 **희망 현금 입력란이 없다**
- [ ] 직급이 `팀장`/`팀원` 선택 + 직접 입력을 모두 지원한다
- [ ] 각 입력에 §5.1 표의 포맷 예시가 placeholder로 보인다
- [ ] 이름 검색이 부분일치로 좁히고, 지우면 전체 복원된다
- [ ] `상세` 버튼으로 전체 인사 정보 Dialog가 열린다
- [ ] 목록에 직급 컬럼이 보인다
- [ ] `직원별 월간 급여 롤업`이 화면·코드에 없다
- [ ] `근무 인원 수별 평균` 테이블이 없다
- [ ] `월간 생산성/인력 배치 분석`은 그대로 동작한다
- [ ] 4개 신규 필드를 비운 채 저장해도 성공한다
- [ ] 기존 직원 레코드가 마이그레이션 후 오류 없이 조회·수정된다

### 8.2 [B] 인건비 리포트

- [ ] 지점 요약 `근무인원 일평균`이 `합계 ÷ 근무일 수`(소수 2자리)와 일치한다
- [ ] `근무일 수 = 0`이면 `-`이고 오류가 없다
- [ ] 기간 모드에서 `from`~`to` 범위 장부만 집계된다
- [ ] `?month=2026-07` 기존 URL이 동작한다
- [ ] `from > to` 또는 366일 초과 시 오류 + 현재 월 폴백
- [ ] `근무자별 월 정산`에 근무자·직급·근무일수·인건비 합계·희망 4대보험·희망 현금(자동)·계좌번호가 보인다
- [ ] `희망 현금(자동)`이 강조되고 `자동` 배지·계산식이 보인다
- [ ] 희망 현금 음수가 그대로 표시되고 경고 배지가 뜬다
- [ ] 4대보험 미입력 / 직원 미연결이 각각 사유와 함께 `계산 불가`
- [ ] 다월 조회 시 `기간 합계 기준` 배지 + 자동계산 미적용 사유
- [ ] 일별 상세에 희망 금액 2컬럼이 없다
- [ ] 일별 상세 합계 = 월 정산 합계 = 지점 요약 합계

### 8.3 [C] 월간 핵심 성과

- [ ] 카드 그리드가 없고 2행 테이블이다
- [ ] 1행: 매출 · 이익률 · 영업이익 · 인건비 · 순이익(순이익률)
- [ ] 2행(비강조): 평균재고 · 손실 합계 · 평균매출
- [ ] `장부 마감 매출`·`이월 매출`·`매출이익`·`매출대비 재고비율`이 없다
- [ ] **`영업이익`·`순이익` 헤더에 계산식이 병기된다** (R-1)
- [ ] `순이익 = 영업이익 − 인건비`가 수치로 검증된다
- [ ] 영업이익이 `계산 불가`면 순이익도 사유와 함께 `계산 불가`
- [ ] 매출 ≤ 0이면 순이익률이 `-`
- [ ] 통합 리포트에 `장부 마감 매출`·`이월 매출`이 남아 있다
- [ ] CSV/XLSX export 결과가 변경 전과 동일하다

### 8.4 [D] 매출분석 3종

- [ ] 월간에 증감률·매출 비중·재고비율 3개 차트가 보인다
- [ ] 증감률 라벨이 `전월 대비`다
- [ ] 지점 미선택 상태에서도 렌더링된다
- [ ] 직전 월 데이터 없으면 사유와 함께 `계산 불가` 목록
- [ ] 차트 지점별 매출값이 같은 월 `monthly-profit-loss`의 `salesAmount`와 일치한다

### 8.5 [E] 권한

- [ ] `OWNER` 계정에만 사이드바 `인건비 현황`·`직원 관리`가 보인다
- [ ] `HQ_ADMIN`·`HQ_READONLY`·`SETTINGS_ADMIN`에는 보이지 않는다
- [ ] 위 계정이 두 경로에 **직접 URL 접근 시** `/app/unauthorized`로 리다이렉트된다
- [ ] `ReportsNav`의 `인건비` 링크가 비대표 계정에 렌더링되지 않는다
- [ ] 지점장은 두 화면에 접근할 수 없다
- [ ] 지점장 장부 급여 입력의 직원 선택이 정상 동작한다
- [ ] 비대표 계정이 직원 CRUD 서버 액션을 직접 호출해도 거부된다
- [ ] 월간의 `인건비`·`순이익`은 `REPORT_VIEW` 계정에도 보인다
