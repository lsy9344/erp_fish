## 2. 현행 코드 검토 결과

### 2.1 리포트 계층이 이미 계산과 인가를 모두 한다 — 도구는 얇은 위임이다

| 도구                     | 위임 대상                                                                    | 자체 authz                                |
| ------------------------ | ---------------------------------------------------------------------------- | ----------------------------------------- |
| `get_period_metrics`     | `getHqPeriodContrastReport` (`reports/queries.ts:757`)                       | 내부 `getHqStoreComparisonReport` 경유    |
| `get_month_overview`     | `getHqReportOverview` (`reports/overview.ts:950`)                            | `requireReportAccess` + 지점 scope (:967) |
| `get_product_sales`      | `getHqProductSalesReportForRange` (`reports/queries.ts:1565`)                | `requireReportAccess` (:1576)             |
| `get_monthly_pnl`        | `buildMonthlyProfitAndLoss` (`reports/monthly-profit-loss.ts:74`)            | `requireReportAccess` (:82)               |
| `get_labor_report`       | `getHeadquartersLaborReport` (`labor/headquarters-labor-queries.ts:506`)     | **`requireLaborViewAccess`** (:524)       |
| `get_inventory_position` | `getHqInventoryPositionReport` (`reports/inventory-position-queries.ts:282`) | 동일 패턴                                 |

**판정** — 챗봇에 인가 코드를 새로 쓰지 않는다. `get_labor_report`의 대표 전용 게이트도 위임만으로 성립한다. 도구가 직접 `db`를 import하면 이 판정이 깨진다. **금지한다.**

### 2.2 `매출`은 컬럼이 아니다 — 도구가 직접 집계하면 대시보드와 어긋난다

- `applied.totalSales` = `operatingSales` = 마감 매출 + 이월 매출 (`server/calculations/ledger.ts:785`)
- 그 위에 `getLatestCorrectionValuesForLedgersScoped`의 최신 정정값이 덮인다 (`reports/queries.ts:2146`)
- `grossProfit`은 매출원가 산출 가능한 장부만 합산 (`reports/queries.ts:2047-2052`)

**판정** — 도구는 반환값을 **재계산하지 않는다.** 정렬·상위 N 절단·필드 선택만 허용한다. 합계를 다시 더하는 코드가 보이면 리뷰에서 반려한다.

### 2.3 원인 분석 근거가 이미 계산돼 있다

`HqReportOverviewData` (`reports/overview.ts:15-120`)가 다음을 이미 담고 있다.

- `profitAndLoss.steps` — 매출 → 원가 → 인건비 → 고정비 → 순익 워터폴 (`kind: "increase" | "decrease" | "total"`)
- `lossBreakdown.items` — 손실 항목별 금액·비중
- `rankings` — 지표별 지점 순위 + **제외 사유**
- `actions` — `severity` 붙은 경보
- `dataQuality.missingCount` — 미마감 일수

**판정** — LLM은 추론하지 않고 **읽는다.** 그래서 소형 모델로 충분하다(C-3).

### 2.4 직원 PII가 인건비 경로에 있다

`EmployeeListItem` (`labor/employees-queries.ts:5-23`)에 `bankAccount`·`address`·`phone`이 있다.

**판정** — `get_labor_report` 출력은 **명시 allowlist**로 통과시킨다(C-5). `src/server/sensitive-fields.ts`의 `omitSensitiveFields`를 **재사용하지 않는다** — 그 함수는 지점장에게 원가·마진을 숨기는 반대 방향 마스킹이고, 본사 챗봇 사용자는 그 값을 볼 권한이 있다.

### 2.5 외부 연동 환경변수는 `process.env` 직접 참조가 기존 방식이다

`INTERNAL_CRON_SECRET`·`LINE_CHANNEL_ACCESS_TOKEN`·`LINE_API_BASE_URL` 모두 `src/env.js`에 없고 `process.env`를 직접 읽는다 (`api/internal/notifications/morning-summary/route.ts:15-25`, `notifications/line-client.ts:15`). 테스트는 `playwright.config.ts:38-46`의 `webServer.env`로 주입하며 `SKIP_ENV_VALIDATION: "1"`이 걸려 있다.

**판정** — `OPENAI_*`도 같은 방식. **`src/env.js`를 건드리지 않는다.** 미설정 시 503으로 명시 처리한다(§3.C).

### 2.6 외부 API 스텁 패턴이 이미 있다

`LINE_API_BASE_URL` → `src/app/api/test/line-stub/...` (`line-stub` route는 `NODE_ENV === "production"`이면 404). 그대로 복제한다.

### 2.7 라우트 핸들러에서 authz는 redirect를 던진다

`api/reports/export/route.ts:40-52`가 `isNextRedirectError`로 잡아 403으로 변환한다. 동일 처리를 한다.

## 3. 확정 구현 정책

### 3.A LLM 클라이언트

`src/features/chat/llm-client.ts`

```
callChatModel({ system, tools, messages }) → { content, toolCalls, finishReason }
```

- `fetch`로 OpenAI Chat Completions 호출. SDK 없음.
- Base URL: `process.env.OPENAI_API_BASE_URL ?? "https://api.openai.com"` — `line-client.ts:15-19`와 동일 구조.
- 모델: `process.env.OPENAI_CHAT_MODEL ?? <소형 기본값>`.
- **메시지 배열 맨 앞은 항상 `system` + 도구 스키마 순서 고정** (C-6). 사용자별로 달라지는 내용을 앞에 섞지 않는다.
- 타임아웃 20초(`AbortSignal.timeout`). 자동 재시도 없음.
- 실패는 throw하지 않고 `{ status: "error", error }` 반환 — `sendLineMessage`와 동형.

### 3.B 도구 계층 — 이 작업의 핵심

`src/features/chat/tools.ts`

각 도구는 **인자 정규화 → 기존 함수 호출 → 출력 allowlist**만 한다.

#### 공통 인자 정규화

| 항목      | 규칙                                                                                                 |
| --------- | ---------------------------------------------------------------------------------------------------- |
| 날짜      | `getKstBusinessDate` (`features/ledger/date.ts`)로 검증. 형식 위반은 도구 오류 결과                  |
| 기간 상한 | 366일. 초과 시 오류 결과(조용히 자르지 않는다)                                                       |
| 월        | `YYYY-MM`. `getHeadquartersExpenseMonthRange` / `getMonthlyClosingAnomalyReportMonthRange` 기존 파서 |
| 지점명    | 공백 제거 후 부분 일치. **1건이면 채택, 0건·2건 이상이면 후보 목록을 담은 오류 결과** — 추측 금지    |
| `limit`   | **서버가 강제.** LLM이 200을 넣어도 20에서 자른다                                                    |

#### 출력 allowlist (C-5)

| 도구                     | 통과 필드                                                                                                                                                                                                                                                                                                                                                                                                                             | 제거                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `get_period_metrics`     | `storeName` + 8지표(`salesAmount`, `grossProfit`, `grossMarginRate`, `averageWorkerCount`, `productivity`, `averageInventory`, `averageSales`, `inventoryToSalesRatio`), `contrastRows{metricLabel, base, current, delta, deltaKind}`, 기간 라벨                                                                                                                                                                                      | `storeId`, `detailHref`, 원본 행 전체                                                     |
| `get_month_overview`     | `summary`(deprecated `salesAmount` 제외), `profitAndLoss{available, reason, steps[{label, amount, kind}]}`, `lossBreakdown{items[{name, amount, ratio}], totalAmount, uncomputableCount}`, `salesTrend[{dateInput, currentAmount, previousAmount}]`, `rankings[지표]{rows[{storeName, value}] 상위5, excluded[{storeName, reason}]}`, `closingStatus[{label, count}]`, `actions[{storeName, label, detail, severity}]`, `dataQuality` | `detailHref` 전량, `storeId`(cuid), `chartSummaries`, `stores`, `closingMissingDays` 원본 |
| `get_product_sales`      | `productName`, `productSpec`, `productCategory`, `soldQuantity`, `estimatedSalesAmount`, `lossQuantity`, `statusLabel` — **상위 N만**                                                                                                                                                                                                                                                                                                 | `productId`, 상위 N 밖 전량                                                               |
| `get_monthly_pnl`        | `storeName`, `salesAmount`, `cogsAmount`, `grossProfit`, `grossMarginRate`, `laborAmount`, `fixedCosts`, `otherExpenseAmount`, `hqAdjustmentAmount`, `netAmount`, `adjustmentReason`                                                                                                                                                                                                                                                  | `storeId`, `memo`                                                                         |
| **`get_labor_report`**   | `workerName`, `storeName`, `workedDayCount`, `dailyWage`, `laborAmount`, 합계                                                                                                                                                                                                                                                                                                                                                         | **`bankAccount`, `address`, `phone`** + 행 단위 원본                                      |
| `get_inventory_position` | `storeName`, `productName`, `quantity`, `amount`, 장기재고 플래그 — **상위 N만**                                                                                                                                                                                                                                                                                                                                                      | `storeId`, `productId`, `detailHref`                                                      |

allowlist는 **필드명을 나열한 상수**로 만든다. 스프레드(`...row`) 후 삭제하는 방식은 금지한다 — 원본에 필드가 추가되면 조용히 새어 나간다.

#### 부분 계산 신호

`ledgerCount !== computableLedgerCount`이거나 `statusLabel`이 `"추정"`/`"계산 불가"`이면 결과에 `partial: true`와 사유를 실어 보낸다. 프롬프트가 이를 답변에 반영한다(§3.D).

### 3.C API 라우트

`src/app/api/chat/route.ts`

```
POST /api/chat
 1. requireReportAccess()            — isNextRedirectError → 403 forbidden
 2. zod 검증: messages[], 각 content ≤ 500자, 최근 12턴만 사용
 3. rate limit: 사용자당 분당 10회
 4. 도구 루프 (최대 3라운드)
      · callChatModel → toolCalls 있으면 인자 zod 재검증 → 실행 → allowlist → 결과 회신
      · 도구 실행 예외는 삼키지 않고 오류 텍스트로 회신 (LLM이 사과하게)
 5. { reply, usedTools } + Cache-Control: no-store
```

| 상태 | `error`           | 조건                                       |
| ---- | ----------------- | ------------------------------------------ |
| 400  | `bad_request`     | 스키마 위반, 500자 초과                    |
| 403  | `forbidden`       | `REPORT_VIEW` 없음                         |
| 429  | `rate_limited`    | 분당 상한 초과                             |
| 503  | `llm_unavailable` | `OPENAI_API_KEY` 미설정 또는 LLM 호출 실패 |

**rate limit 구현**: 모듈 스코프 `Map<userId, {count, windowStart}>`.

```
// ponytail: 인스턴스별 카운터다. 다중 인스턴스에서는 상한이 인스턴스 수만큼 늘어난다.
// 남용 방지용이지 보안 경계가 아니다. 정확한 상한이 필요해지면 DB 카운터로 바꾼다.
```

**거절 로그**: 도구를 하나도 못 쓴 응답은 구조화 로그 1줄(`console.info`)로 남긴다 — 질문 원문 + `usedTools: []`. **DB 테이블을 만들지 않는다**(마이그레이션 0건 유지). 도구 카탈로그 확장 근거로 쓴다(설계 §경계).

### 3.D 시스템 프롬프트

`src/features/chat/prompt.ts` — 고정 블록 + 하루 단위로만 바뀌는 값만 담는다(C-6).

주입: 오늘 KST 날짜(`getTodayKstInput()`), 접근 가능 지점명 목록.

강제 규칙:

1. 연도 없는 월(`12월`)은 오늘 기준 가장 가까운 과거로 해석하고 **해석 결과를 답변에 명시**한다
2. **도구 결과에 없는 숫자는 말하지 않는다** — 추정·보간·암산 금지
3. 도구로 답할 수 없으면 거절한다
4. 지점 모호·기간 불명확이면 되묻는다
5. 원인은 **숫자 차이로만** 뒷받침한다. `~때문입니다`(인과 단정) 대신 `~가 가장 큰 감소 요인입니다`
6. `partial`·`추정`·`미마감`(`dataQuality.missingCount > 0`)은 한 문장으로 덧붙인다
7. `계산 불가`·`null`을 0으로 취급하지 않는다
8. 금액 천 단위 구분, 비율 소수 둘째 자리(`src/lib/format.ts` 표기와 일치)
9. 답변 2~4문장 평문

## 4. 구현 순서

각 단계는 **그 단계만으로 검증 가능**해야 한다. 다음 단계로 넘어가기 전에 검증 명령이 그린이어야 한다.

| 단계 | 덩어리 | 작업                                        | 검증                                                 |
| ---- | ------ | ------------------------------------------- | ---------------------------------------------------- |
| 1    | B      | 도구 6개 + 인자 정규화 + **allowlist 상수** | `pnpm test:unit:file tests/unit/chat-tools.test.mjs` |
| 2    | A      | `llm-client.ts` + `openai-stub` 라우트      | `pnpm typecheck`                                     |
| 3    | C      | `/api/chat` — authz·검증·루프·rate limit    | `pnpm test:playwright tests/api/chat.spec.ts`        |
| 4    | D      | 프롬프트 + 실제 키로 수동 질의 (예시 4문항) | 수동 — §7.5                                          |
| 5    | E      | 위젯 + 셸 마운트                            | `pnpm test:playwright tests/e2e/chat-widget.spec.ts` |
| 6    | F      | 배포 설정 · 문서                            | `pnpm check && pnpm build`                           |
| 7    | —      | 회귀 확인                                   | `pnpm test:e2e:core` — **기존 테스트 무변경 그린**   |

**1번을 먼저 하는 이유**: 도구 계층은 LLM 없이 단위 테스트로 전부 검증된다. 여기가 가장 크고 가장 틀리기 쉽다. LLM을 붙인 뒤 디버깅하면 원인이 도구인지 모델인지 구분이 안 된다.

**7번이 실패하면 설계 이탈이다.** 이 작업은 기존 코드를 읽기만 한다. 기존 테스트가 깨지면 도구가 기존 함수를 변형했다는 뜻이다.

## 7. 수용 기준

### 7.1 [B] 도구 계층

- [ ] 6개 도구가 모두 기존 리포트 함수에 위임한다. **`tools.ts`에 `db` import가 없다**
- [ ] 도구가 반환값을 재계산·재합산하지 않는다 (정렬·절단·필드 선택만)
- [ ] 지점명 정확 일치 → 채택
- [ ] 지점명 부분 일치 1건 → 채택
- [ ] 지점명 2건 이상 매칭 → 후보 목록을 담은 오류 결과 (**임의 선택 안 함**)
- [ ] 권한 범위 밖 지점명 → 접근 가능 목록 반환
- [ ] 잘못된 날짜 형식 → 오류 결과 (예외 throw 아님)
- [ ] 366일 초과 기간 → 오류 결과 (조용히 자르지 않음)
- [ ] `limit=200` 요청 → 20으로 절단
- [ ] **`get_labor_report` 출력에 `bankAccount`·`address`·`phone`이 없다**
- [ ] allowlist가 필드명 상수 나열이다 (스프레드 후 삭제 방식 아님)
- [ ] `get_month_overview` 출력에 `detailHref`가 하나도 없다
- [ ] `ledgerCount !== computableLedgerCount`이면 `partial: true`와 사유가 실린다

### 7.2 [C] API 라우트

- [ ] 미인증 요청 → 403
- [ ] `REPORT_VIEW` 없는 계정 → 403
- [ ] `LABOR_VIEW` 없는 계정의 급여 질문 → 도구 실행 차단, 답변은 권한 안내
- [ ] 501자 메시지 → 400
- [ ] `messages` 누락·형식 오류 → 400
- [ ] `OPENAI_API_KEY` 미설정 → 503 `llm_unavailable`
- [ ] LLM 타임아웃 → 503 (자동 재시도 없음)
- [ ] 도구 실행 예외가 500으로 새지 않고 대화로 처리된다
- [ ] 4라운드째 도구 호출이 시도되지 않는다
- [ ] 분당 11번째 요청 → 429
- [ ] 응답 헤더에 `Cache-Control: no-store`
- [ ] 도구를 못 쓴 응답이 거절 로그를 남긴다

### 7.3 [D] 프롬프트 · 답변 품질

- [ ] `12월 매출` → 연도를 해석하고 **해석한 연월을 답변에 명시**한다
- [ ] 도구 결과에 없는 숫자가 답변에 등장하지 않는다
- [ ] 지원하지 않는 질문에 지어내지 않고 거절한다
- [ ] `추정`·`부분 합계`·`미마감`이 답변에 반영된다
- [ ] `계산 불가`를 0으로 말하지 않는다
- [ ] 원인 질문 답변에 `~때문입니다` 형태의 인과 단정이 없다

### 7.4 [E] UI

- [ ] 본사 전 화면 우하단에 원형 아이콘이 보인다
- [ ] **지점장 화면에는 아이콘이 없다**
- [ ] 클릭하면 채팅창이 열리고 아이콘이 숨는다
- [ ] ESC·오버레이 클릭으로 닫힌다
- [ ] 예시 질문 버튼 클릭 = 해당 문장 전송
- [ ] 전송 중 입력이 비활성화되고 진행 표시가 보인다
- [ ] 에러가 말풍선으로 대화에 남는다 (토스트 아님)
- [ ] 대화 내용이 새로고침 후 사라진다 (영속화 안 함이 의도)

### 7.5 [수동] 실제 키 검증 — 4문항

각 답변의 숫자를 **해당 리포트 화면과 대조**한다. 하나라도 어긋나면 §2.2 위반이다.

- [ ] `8월 1일 강서수산 매출 얼마야` → 대시보드 해당일 `매출`과 일치

- [ ] `7월에 가장 많이 팔린 품목` → `/app/reports/product-review` 상위와 일치
- [ ] `지난달 순익이 줄어든 원인` → `/app/reports/overview` 워터폴 단계와 일치, 근거 수치 제시
