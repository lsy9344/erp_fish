- 상태: 부분 즉시 착수 가능 / 정책 결정 4건과 UI 시안 확인 1건 필요

## 1. 목표

Notion `0905`의 요청을 현재 코드와 실제 데이터에 맞춰 구현한다.

이번 작업은 다음 원칙을 지킨다.

1. 이미 구현된 기능은 다시 만들지 않고 부족한 부분만 고친다.
2. 화면에서 잘못 보이는 문제와 실제 데이터 문제를 분리한다.
3. 월 보험료, 지점 순위, 냉동 전환처럼 계산 의미가 바뀌는 항목은 조용히 규칙을 바꾸지 않는다.
4. 지점장에게 원가·급여 같은 본사 전용 값이 새로 노출되지 않게 한다.
5. 모든 변경은 단위 테스트와 실제 화면 테스트로 확인한다.

## 3. 조사 결과

### 3.1 근무인원 선택

현재 `WorkStepClient`는 이미 다음 기능을 갖고 있다.

- 직원 선택 목록을 `매니저`, `팀원`, `직급 미지정`으로 그룹화한다.
- 근무인원을 직접 입력하지 않는다.
- 근무자 저장 시 서버가 저장된 근무자 행 수로 `DailyLedger.workerCount`를 갱신한다.
- 지점장과 본사의 급여 노출 권한을 나눈다.

남은 차이는 화면 배치와 표시 문구다.

- 지금은 한 직원 행을 추가한 뒤 한 드롭다운 안에서 직급을 고른다.
- 요청은 직급별 선택 영역을 별도 카드로 바로 보이게 하는 것이다.
- 현재 저장 전 미리보기는 `laborItems.length`라 직원을 고르지 않은 빈 행도 1명으로 보일 수 있다.
- 현재 옵션은 `이름 (매장 · 직급 · 입사일)`이다.

### 3.3 기간대조 지표

현재 8개 지표 목록 `PERIOD_ANALYSIS_METRICS`를 기간대조와 월별추이가 같이 쓴다. 이 공용 목록에서 `매출이익`을 바로 지우면 월별추이의 지표 선택과 Excel까지 함께 사라진다.

Notion 요청은 `기간대조 페이지의 모든 테이블`로 한정되어 있다. 따라서 기간대조 전용 목록을 만들어 아래 3개 표에서만 `매출이익`을 제외한다.

1. 대조 기간
2. 현재
3. 과거 대비 현재 증감

평균 근무인원 증감은 현재 금액 지표처럼 증감률로 계산되어 `%`로 보인다. 새 요청에서는 비율이 아니라 아래처럼 사람 수 차이를 보여야 한다.

```text
평균 근무인원 증감 = 현재 평균 근무인원 - 대조 기간 평균 근무인원
표시 예: 2.4명 → 3.5명 = +1.1명
```

### 3.4 월별추이 날짜 입력

`mode=trend`는 연도, 기간 단위, 축, 월 범위로 조회한다. 화면 상단의 공통 `시작일`과 `종료일`은 추이 결과 계산에 쓰이지 않는다.

따라서 추이 모드에서는 공통 시작일·종료일 입력을 숨긴다. 연도별 시즌 비교에 실제로 쓰이는 `월 범위`는 삭제하지 않는다.

### 3.5 8월 지점 성과 순위

현재 순위는 선택한 달의 모든 날짜가 아래 둘 중 하나여야 계산에 넣는다.

- 휴무
- 검토 중 또는 본사 마감된 정상 장부

2026년 8월 데이터 확인 결과는 다음과 같다.

| 지점       | 미입력 | 진행 중 | 결과      |
| ---------- | -----: | ------: | --------- |
| 안양참수산 |    0일 |     0일 | 순위 포함 |
| 제일유통   |    5일 |     6일 | 제외      |
| 삼국유통   |    5일 |     3일 | 제외      |
| 불광       |    5일 |     1일 | 제외      |
| 못골       |    1일 |     4일 | 제외      |
| 구로       |    4일 |     2일 | 제외      |
| 강서       |    5일 |     0일 | 제외      |

안양만 보이는 직접 원인은 순위 코드 오류가 아니라 다른 지점의 월 데이터가 완성되지 않은 것이다. 과거 Excel 자료의 8월 행이 섞여 생긴 문제도 아니다.

권장 결정:

- 월 전체 비교라는 현재 뜻을 유지한다.
- 미입력·진행 중 데이터를 먼저 보완한다.
- 순위 카드에는 제외 지점별 `미입력 n일 · 진행 중 n일`을 보여준다.
- 일부 날짜만 있는 지점을 억지로 순위에 넣지 않는다.

부분 월 순위가 꼭 필요하면 `완료된 날짜 수 / 월 전체 날짜 수`를 함께 보여주는 별도 모드로 설계한다. 기존 순위 규칙을 조용히 약하게 바꾸지 않는다.

### 3.6 김상우 20일/1일 중복

2026년 8월 데이터 확인 결과:

- 20일 행은 직원 카드 ID와 연결되어 있다.
- 2026-08-31 안양참수산의 한 인건비 행만 `employeeId=null`이다.
- 리포트는 연결된 직원은 직원 ID로, 미연결 직원은 `지점+이름`으로 묶는다.
- 따라서 같은 이름이어도 안전을 위해 두 사람으로 나뉘어 20일/1일로 표시된다.

이 동작은 동명이인을 잘못 합치지 않기 위한 안전 규칙이다. 리포트에서 이름만 보고 합치면 안 된다.

수정 대상 데이터는 작업 직전에 다시 조회해 한 건인지 확인한다.

- 미연결 인건비 행: `cmth317pt00dijq04ns8c7f1k`
- 연결할 직원 카드: `cmtc5oj1z000pl404l54ilzks`

권장 수정:

1. 가능하면 본사 장부 수정 화면에서 해당 행을 김상우 직원 카드와 연결한다.
2. 화면에서 수정할 수 없으면 정확한 ID 한 건만 고치는 복구 스크립트를 만든다.
3. 스크립트는 기본 dry-run, 대상 1건 확인, 변경 전후 출력, 감사로그 기록을 필수로 한다.
4. 수정 후 김상우가 한 행 21일로 보이는지 확인한다.
5. 앞으로 저장되는 지점장 근무 행은 직원 선택이 없으면 저장되지 않게 서버 검증을 강화한다. 기존 과거 미연결 데이터는 자동 병합하지 않는다.

### 3.7 지점 필터의 희망 현금

현재 계산식은 다음과 같다.

```text
희망 현금 = 한 달 인건비 합계 - 희망 4대보험
```

희망 4대보험은 직원별 월 고정액이다. 현재 코드는 지점·상태·이름 필터로 월 급여 일부만 남은 상태에서 보험료 전액을 빼는 오류를 막기 위해 희망 현금을 계산하지 않는다. 화면의 `필터 조회에서는 자동계산 미적용`은 이 안전 규칙이다.

권장 변경안:

- 조회 기간이 한 달 전체일 때만 희망 현금을 계산한다.
- 지점·상태·이름 필터는 어떤 직원을 화면에 보여줄지에만 사용한다.
- 표시되는 직원의 희망 현금은 필터 전 `그 직원의 월 전체 인건비 합계`로 별도 계산한다.
- 셀에는 `월 전체 기준` 배지와 계산식을 보여준다.
- 여러 달 또는 한 달의 일부 기간 조회는 지금처럼 계산하지 않고 이유를 표시한다.
- 직원이 여러 지점에서 근무했다면 직원 ID 기준 전 지점 월 합계를 사용한다.

이 방식이면 지점 필터에서도 값이 보이면서 월 보험료를 일부 급여에서 잘못 빼지 않는다.

### 3.8 Excel 내보내기

현재 일별·기간분석·월간·재고 리포트에는 이미 Excel 내보내기가 있다. 공용 생성기는 `ReportExportSheet`를 받아 헤더, 열 너비, 여러 시트를 만든다. 인건비 리포트만 화면과 API 연결이 없다.

### 3.10 냉동 부분 전환

현재 시스템의 `냉동/생물`은 품목 분류다. 생물 재고 일부를 냉동 재고로 옮기는 기능과 기록 테이블은 없다. 기존 손실이나 재고 조정으로 흉내 내면 판매량·원가·FIFO가 틀어지므로 금지한다.

기술적으로 부분 전환은 가능하지만 아래 업무 규칙을 먼저 정해야 한다.

1. 생물 품목마다 연결할 냉동 품목 카드가 이미 있는가?
2. 1개 생물을 냉동하면 냉동도 항상 1개인가, 중량·손질 손실이 있는가?
3. 원가는 그대로 옮기는가, 가공비를 더하는가?
4. 가장 오래된 재고부터 전환하는가, 사용자가 입고 묶음을 고르는가?
5. 전환 취소와 마감 후 수정은 누가 할 수 있는가?

권장 데이터 원칙:

- 전환은 반드시 재고 단계에서만 입력한다.
- `전환 수량 > 0`이고 `전환 수량 <= 전환 전 남은 수량`이어야 한다.
- 원본 품목, 대상 냉동 품목, 수량, 원가 근거, 작업자, 작업 시각을 별도 전환 기록으로 남긴다.
- 원본 FIFO 묶음에서 수량을 차감하고 같은 원가 근거로 대상 냉동 FIFO 묶음을 만든다.
- 전환 수량은 판매나 손실로 계산하지 않는다.
- 부분 전환을 지원한다. 예: 남은 10개 중 5개만 전환하면 원본 5개, 냉동 5개가 남는다.
- 저장 실패 시 원본과 대상 중 한쪽만 바뀌지 않도록 한 트랜잭션에서 처리한다.

필요할 가능성이 높은 변경:

- Prisma migration: 재고 전환 기록과 전환 원가 배분 기록
- `InventoryLotSource`에 전환 원천 구분 추가
- 품목 마스터의 생물→냉동 대상 연결 또는 전환 시 대상 품목 선택
- 재고 조회·저장·FIFO 재계산·이월·감사로그·본사 수정 경로 확장
- 전환 전용 단위 테스트와 E2E

이 항목은 위 5개 업무 규칙이 정해진 뒤 별도 설계서와 migration 계획을 먼저 작성한다. 다른 화면 수정과 한 번에 구현하지 않는다.

### 3.13 전날 재고 보기

현재 팝업은 모든 품목을 한 표에 보여주며 열은 `품목/규격/수량/FIFO 기준일/전일 장부 상태`다.

변경 후 열 순서:

1. 품목
2. 규격
3. 전날 재고 수량
4. 전일 기준 판매량
5. 마지막 입고일
6. 전일 장부 상태

필터:

- `전체`
- `냉동`
- `생물`

계산 규칙:

```text
전일 기준 판매량
= 전날 장부의 시작 재고
+ 전날 장부의 매입
- 전날 장부의 손실
- 전날 장부의 마감 재고
```

- 값은 0 미만으로 만들지 않는다.
- 근거 장부가 없거나 필요한 값이 없으면 `계산 불가`와 이유를 표시한다.
- 현재 날짜의 판매량을 잘못 보여주지 않는다.
- `마지막 입고일`은 전날 마감 시점에 남아 있던 FIFO 묶음 중 가장 최근 입고일이다.
- 오늘 들어온 매입일은 전날의 마지막 입고일에 섞지 않는다.
- 기존 `FIFO 기준일` 열은 제거한다.
- 지점장에게 단가·원가·재고금액은 새로 노출하지 않는다.

현재 `previousQuantityDetail`에 전날 장부의 시작·매입·손실·마감 수량이 있어 판매량은 새 DB 없이 계산할 수 있다. 마지막 입고일은 전날 원천 장부의 FIFO 묶음을 기준으로 서버에서 명시적으로 내려주는 방식을 권장한다.

- 긴 이름, 큰 금액, 오류 문구가 잘리지 않는다.

### Task 10. 장부 작성자 문구 통일

1. 지점장 화면의 `작성자 표시명`을 `장부 작성자`로 바꾼다.
2. 데이터 필드와 저장 규칙은 유지한다.

완료 기준:

- 매입부터 검토까지 같은 사람을 서로 다른 이름으로 부르지 않는다.
- 기존 작성자 값과 감사 이력은 바뀌지 않는다.

### Task 11. 지점장 손실 유형 별칭 편집 제거

1. 지점장 손실 화면에서 별칭 편집기를 제거한다.
2. 손실 유형 선택과 저장은 유지한다.
3. 본사 코드관리의 손실 유형 편집은 유지한다.

완료 기준:

- 지점장은 손실 유형을 선택할 수 있지만 이름을 바꿀 수 없다.
- 본사는 기존 메뉴에서 손실 유형을 관리할 수 있다.

### Task 12. 전날 재고 보기 개선

1. 팝업에 냉동·생물 필터를 추가한다.
2. 전일 판매량을 전날 장부 데이터로 계산한다.
3. 마지막 입고일을 전날 마감 시점 기준으로 내려준다.
4. FIFO 기준일을 제거하고 새 열 순서를 적용한다.
5. 빈 값과 계산 불가 상태를 구분한다.

완료 기준:

- 냉동·생물을 따로 볼 수 있다.
- 판매량과 마지막 입고일이 오늘 데이터와 섞이지 않는다.
- 지점장 DOM과 응답에 원가·금액이 새로 들어가지 않는다.

### Task 13. 냉동 부분 전환 설계

1. 3.10의 업무 질문 5개를 확정한다.
2. 별도 설계서에 데이터 모델, FIFO 이동, 취소, 감사, 마감 수정 규칙을 작성한다.
3. migration과 회귀 범위를 검토한 뒤 별도 구현 작업으로 착수한다.

완료 기준:

- 10개 중 5개 같은 부분 전환 예제가 수량과 원가까지 맞는다.
- 전환이 판매·손실·재고조정으로 잘못 집계되지 않는다.
- 원본과 냉동 대상의 이월 수량이 다음 날에도 맞는다.

## 6. 최종 인수 조건

### 지점장

- [ ] 근무자를 매니저·팀원 카드에서 나눠 선택할 수 있다.
- [ ] 선택한 직원 수가 총 근무인원으로 자동 표시·저장된다.
- [ ] 직원 문구는 `이름 (매장이름)`이다.
- [ ] 매입 화면은 `장부 작성자`라는 말을 쓴다.
- [ ] 지점장은 손실 유형 이름을 바꿀 수 없다.

### 본사 리포트

- [ ] 매출 증감 카드의 겹치는 일반 표가 없다.
- [ ] 기간대조 세 표와 Excel에 `매출이익` 열이 없다.
- [ ] 평균 근무인원 증감은 소수 1자리 `n명`이다.
- [ ] 월별추이에 불필요한 시작일·종료일이 없다.
- [ ] 순위 제외 이유를 지점별로 알 수 있다.
- [ ] 김상우 8월 정산은 한 행 21일이다.

### 인건비·Excel

- [ ] 지점 필터에서도 월 전체 기준 희망 현금이 정확히 보인다.
- [ ] 인건비 Excel을 권한 있는 본사 사용자만 받을 수 있다.
- [ ] 화면과 Excel의 숫자·사유가 같다.

### 재고

- [ ] 데스크톱 2열 시안과 비교 스크린샷이 승인됐다.
- [ ] 승인안 구현 후 스크롤이 줄고 모바일은 1열로 안전하다.
- [ ] 전날 재고를 냉동·생물로 따로 볼 수 있다.
- [ ] 전일 판매량과 마지막 입고일이 정확하다.
- [ ] FIFO 기준일 열이 제거됐다.
- [ ] 냉동 부분 전환은 별도 승인된 규칙과 설계에 따라 구현된다.

## 8. 제외 범위

- 이름만 같은 미연결 직원을 자동으로 합치는 기능
- 미완료 지점을 완료 지점과 같은 기준으로 강제 순위화
- 고객 원본 Excel의 수식·피벗·서식을 그대로 복제하는 작업
- 지점장에게 급여·원가·재고금액을 새로 노출하는 변경
- 기존 손실·재고조정 행으로 냉동 전환을 흉내 내는 구현
- 요청과 무관한 장부 단계, 계산식, 권한 구조의 정리·리팩터링
