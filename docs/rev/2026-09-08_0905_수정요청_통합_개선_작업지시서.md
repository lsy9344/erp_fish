## 2. 우선 수정 작업

### Task 1. 손실 유형 별칭을 본사 전용으로 완전히 전환 — P0

현재 `src/app/app/store-entry/losses/page.tsx`에서 편집기만 제거했다. 그러나 아래 경로가 남아 있다.

- `src/features/master-data/code-alias-actions.ts`: 지점장이 `setLedgerInputCodeStoreAlias`를 직접 호출할 수 있다.
- `src/features/losses/queries.ts`: 지점별 별칭을 읽어 손실 유형 선택지에 적용한다.
- 기존 E2E와 단위 테스트도 지점장 별칭 편집을 정상 기능으로 본다.

작업 내용:

1. 손실 유형 별칭을 만드는·바꾸는 서버 액션을 본사 권한으로 막는다. 비용 항목 등 다른 별칭 정책은 건드리지 않는다.
2. 지점장 손실 화면의 선택지와 저장 데이터 표시에는 본사 등록명을 사용한다.
3. 기존 별칭 행은 즉시 삭제하지 않는다. 감사·롤백을 위해 보존한다.
4. 기존 손실 행을 보여줄 때도 본사 등록명을 쓸지, 저장 당시 이름을 보존할지 정책을 먼저 코드 주석과 테스트에 적는다.
5. `tests/unit/code-store-alias.test.mjs`와 손실 E2E의 낡은 “지점장 별칭 편집” 검사를 권한 거부·본사 관리 유지 검사로 바꾼다.

완료 기준:

- 지점장 화면에 별칭 편집기가 없다.
- 지점장이 직접 서버 액션을 호출해도 손실 유형 별칭이 바뀌지 않는다.
- 지점장 손실 선택지는 본사 등록명만 보인다.
- 본사 코드관리의 손실 유형 수정은 계속 된다.

### Task 2. 기간대조 Excel의 평균 근무인원 증감 수정 — P0

`src/features/reports/export.ts`의 기간대조 Excel 생성부는 `absolute` 증감을 다른 수치와 같은 퍼센트로 처리한다. 따라서 `+1.1명`이 `+110.0%`처럼 잘못 나온다.

작업 내용:

1. `delta.kind === "absolute"`를 별도 처리한다.
2. 화면과 같은 형식으로 `+1.1명`, `-0.5명`, `0.0명`을 쓴다.
3. 기간대조의 대조기간·현재·증감 시트에 `매출이익`이 없는지 함께 확인한다.
4. ExcelJS 결과를 실제로 읽는 API 테스트를 추가한다.

완료 기준:

- 화면과 Excel의 평균 근무인원 증감이 같은 값·같은 단위다.
- Excel에 `%` 또는 `%p`로 잘못 표시되지 않는다.
- 월별 추이 Excel의 기존 `매출이익`은 유지된다.

### Task 3. 재고 입력 화면 2열 구현 — P1

현재 변경은 전날 재고 팝업뿐이며, 재고 입력 카드는 여전히 1열이다.

작업 내용:

1. 실제 품목 데이터로 현재 화면, 2열 기본안, 조밀한 대안의 세 화면을 만든다.
2. 1440×900, 1366×768, 390×844에서 카드 높이·스크롤·오류 문구를 확인한다.
3. 승인안만 `lg` 이상 2열로 적용하고 태블릿·모바일은 1열로 둔다.
4. 저장, 포커스 이동, 오류 안내, 분류 탭, 페이지 처리는 바꾸지 않는다.
5. 긴 품목명·큰 숫자·계산 불가 문구가 잘리지 않는 E2E를 추가한다.

완료 기준:

- 데스크톱 한 화면에 카드 두 개가 보인다.
- 모바일은 가로 넘침이 없다.
- 기존 저장 결과와 입력 순서가 달라지지 않는다.
- 시안 이미지와 화면 크기별 비교 기록이 저장돼 있다.

### Task 4. 인건비 Excel 경로를 완성 — P1

작업 내용:

1. `tests/api/report-export.spec.ts`에 인건비 Excel 성공, 권한 없음, 지점 범위, 필터, 희망 현금 사유 검사를 추가한다.
2. 인건비 화면의 Excel 버튼이 현재 조회 조건을 그대로 전달하는지 확인한다.
3. `report=labor&format=csv`를 지원하지 않을 것이라면 400으로 막는다. 지원할 것이라면 조회조건만이 아니라 전체 인건비 시트를 CSV로 명확히 만든다.
4. 계좌번호·급여·희망 현금이 `LABOR_VIEW`와 `EXPORT_CREATE` 없이 나오지 않는지 직접 URL로 확인한다.

완료 기준:

- 화면과 Excel의 지점요약·근무자월정산·근무상세 값이 같다.
- 필터된 직원의 희망 현금은 월 전체 기준이라는 설명과 값이 같다.
- 성공한 다운로드만 감사 기록을 남긴다.

### Task 5. 김상우 연결 복구를 안전하게 실행 — P1

대상 ID는 원 작업지시서의 두 ID를 사용하되, 실행 직전에 다시 조회한다.

작업 내용:

1. 스크립트 dry-run 결과에 장부 ID, 영업일, 지점, 근무자명, 직원 ID를 남긴다.
2. 연결 작업은 `employeeId`만 바꾸고 기존 `amount`를 조용히 바꾸지 않도록 확인한다. 현재 스크립트는 기존 금액이 0이면 직원 일급으로 바꾸므로, 이 동작은 별도 승인이 없으면 제거한다.
3. 적용 시 본사 계정·사유·감사 ID를 기록한다.
4. 적용 후 김상우가 1행·21일로 보이고 다른 동명이인 행은 변하지 않았는지 확인한다.

완료 기준:

- dry-run과 apply 결과가 같은 대상 1건이다.
- 변경 전후 감사 기록이 있다.
- 2026년 8월 인건비 화면과 Excel에서 중복 행이 사라진다.

## 3. 구조 정리 항목

`src/app/api/reports/export/route.ts`에는 인건비 조회·생성 코드가 본문과 `loadReportExportData`에 두 번 있다. 현재 본문이 인건비를 먼저 처리하므로 뒤의 `case "labor"`는 사실상 쓰이지 않는다.

다음 중 하나로 정리한다.

- 인건비 생성 함수를 하나로 묶어 본문과 fallback이 함께 사용한다.
- 본문에서 반드시 먼저 처리한다면 `loadReportExportData`의 도달하지 않는 `labor` 분기를 제거한다.

목표는 같은 조회가 두 군데에서 달라지는 일을 막는 것이다.
